# 资源对账

项目成员可在“资源对账”面板查看最近一次盘点，并请求重新对账。后台按项目扫描 CacheInstance 和 PVC，报告记录与实际资源的差异；不接管、删除资源，也不改写实例生命周期、凭据或配额预留。

当前覆盖：实例 UID/归属冲突、实例缺失、提交配置与 CR spec 不一致、意外删除、已删除实例重新出现、PVC 归属/状态异常、保留卷缺失、删除后残留卷，以及项目 namespace 中未登记的 CR/PVC。进行中的实例操作暂缓判断，展示为 InProgress；Healthy 仅表示该次扫描未发现这些资源差异，不证明缓存请求、监控或所有 Kubernetes 子资源正常。

`GET /v1/projects/{projectId}/inventory` 返回 result 与 checkedAt；首次扫描前两者可为 null。结果区分 Healthy、Drift、InProgress、Unavailable，附问题清单、问题总数及资源数量。错误或权限失败不生成空的健康清单。界面显示最近核对时间，超过五分钟标记过期。

`POST /v1/projects/{projectId}/inventory/refresh` 受项目成员授权与现有 Origin/CSRF 保护，返回 202/scheduled。请求会合并，上一轮扫描后至少间隔十秒；正在进行的扫描可满足该请求。界面每十秒读取结果。常规后台扫描间隔六十秒，平台状态在扫描期间变化时五秒后重试。

后台以三分钟数据库租约分工，网络读取期间不持有项目行锁；发布时校验租约仍属于本 worker，并重新比较实例绑定及操作记录指纹。其他 worker 接管后的迟到结果不能覆盖新观察，扫描期间提交的操作不会被报告为确定差异。集群 namespace 在列表读取前后核对 UID/归属；扫描失败不释放任何资源额度。

为限制单轮资源消耗，数据库最多扫描 1000 个实例绑定，CR/PVC 各最多五页、每页 200 个；遇到未完成分页或超限返回 Unavailable，而不是将截断结果当作完整。差异详情最多显示 200 条，另返回完整问题数量与 truncated 标记。较大项目的分片扫描与历史归档仍需扩展。

本地测试覆盖身份、归属、配置差异、缺失保留卷、孤立资源、分页上限、namespace 替换、数据库租约、多副本跳过、迟到结果、并发操作与只读权限；真实 Helm/API 测试已加入未登记 PVC 注入、观察差异、不自动删除及人工移除后的恢复，已通过提交 3872cfe 的[完整隔离集群 CI](https://github.com/expbuild/expbuild/actions/runs/36679678906)，覆盖内部、Gateway 和 Cilium 模式。

后续仍需其他差异的明确修复流程、额外 Pod/Secret/路由等资源清查和保留卷领回。当前扫描不替代这些能力。

对账同时检查独立保存的模板名称/版本与实际 CR 是否一致，缺失绑定版本会报告未知。资源预留校验比较 CR 的存储需求、CPU/内存请求及限制，以及已归属 PVC 的请求和实际容量；实际配置大于账面预留、预留未知或数量无法解析均报告差异。暂停实例仍核对恢复所需的预留；detached 实例仅核对存储。历史预留高于当前配置不自动释放或报作不足。数量使用精确整数比例比较，小数 CPU、二进制容量和指数格式不依赖浮点舍入。模板和预留字段纳入扫描指纹，扫描期间变更会撤回确定结论并重新扫描。自动扫描只报告差异，不自行改账，也不将存储容量当作文件实际占用。

平台管理员现在可对单个稳定实例调用 `POST /v1/projects/{projectId}/instances/{instanceId}/reservations/reconcile`，界面仅在新鲜、未截断且没有该实例其他异常的对账结果中显示入口。请求重新扫描项目 namespace，核对 CR/PVC 的项目标记、实例 UID、模板与配置，并在项目行锁内复查扫描期间的绑定和操作指纹。只有 active 或 detached 实例可处理；进行中的操作、缺失资源、归属冲突、未知或无法安全表达的数量均拒绝。存储取 CR 需求、PVC 请求和实际分配容量的最大值；运行实例的 CPU/内存取请求与限制的最大值，按账面单位向上取整。数据库只提高历史预留，不降低预留、不修改 Kubernetes 资源；detached 仅校正存储。即使实际用量已超过项目上限，也如实记账，后续新增或扩容会被现有配额准入拒绝。每次处理写审计并安排重新扫描。Kubernetes 与数据库没有跨系统原子快照，外部在扫描后继续扩容仍需由后续对账发现；这不是自动接管或通用修复流程。
